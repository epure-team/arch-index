## Goal

Add to arch-index the layer that **executes** a mutation campaign, on top of the static targeting
already shipped. Today `arch-mutants` can say which functions are worth mutating and which tests
reach each one (`plan`), and can attribute a survivor reported by an external engine back to a
function and to the tests that failed to kill it (`report`). Nothing runs the campaign, nothing is
persisted, and no verdict of arch-index's own is produced. The five slices are the driver
(`arch-mutants run`), two persisted tables, diff-scoped selection, a per-added-test defect
verdict, and per-framework test-invocation profiles.

The value is a gate for machine-written change. With code and tests generated by the same model,
coverage stops measuring anything, and the dominant degradation is a weakened test with no
production line touched. Only mutants of the code that test covers can reveal it. This is
ambition A of the roadmap made executable: "tests green over a change the tests never reach".

**The correctness constraint is not new, and research established that.** Every consumer in this
repository that reaches a verdict already widens on ⊤: `arch-rules` returns `UNKNOWN` rather than
`PASS`, `arch-query unreachable` the same, `dead-code` degrades to `candidate`, `pure-fns` widens
the impure set, `may-fail` returns `UNBOUNDED (⊤)`, `arch-impact` keeps a separate may-bucket, and
`arch-coverage` keeps `covered_via_top_only` distinct. **`arch-mutants` is the only one that does
not.** It filters the ⊤ escapes to the test cone and describes them in prose, and that prose
reaches no verdict. So the arbitrated rule — a survivor under ⊤-bounded selection is `UNKNOWN`,
never `SURVIVED` — is this repository's own house rule applied to the one tool that skipped it.

## Architecture Notes

**The ⊤ contract is the spine.** `lib/arch_tools/arch_graph.ml:99–113` routes a `MAY_TOP` edge into
a separate `tops` frontier map and never into `fwd`/`bwd`/`must_fwd` — "never dropped, never
traversed". So every backward closure is a *lower bound* on the tests that reach a function.
Running only that set is an exclusion, and an exclusion is what a lower bound cannot license.

**Two distinct unknowns exist already.** `arch-rules` separates `UNKNOWN` (the cone escaped through
a ⊤ edge) from `UNKNOWN_NO_CONTRACT` (no escape, but the index is not ⊤-marked at all, so
soundness was never established). Its header states the rule: an index that is not ⊤-marked can
never yield `PASS`. A mutation verdict inherits the same two failure modes and should not collapse
them into one.

**Prior art exists for the vocabulary.** Stryker's Mutation Testing Elements publishes a versioned,
cross-language JSON schema whose status enum separates `NoCoverage` and `Pending` from `Survived`;
PIT has `NO_COVERAGE`. Neither is the same as the `UNKNOWN` needed here — theirs means "no test
covers this line", ours means "the selection we executed may have been incomplete" — but the
precedent is that a richer status set is normal, not exotic.

**Per-test coverage is not free, and its availability is uneven.** pytest attributes coverage to an
individual test natively via coverage.py dynamic contexts. OCaml requires one process per test,
each producing its own bisect_ppx file; under tezt this additionally needs the SIGTERM flush
handler, because parallel workers are killed with SIGTERM and skip the at-exit hook. Go and Rust
have no native per-test coverage at all. This matters because per-test coverage is the additive
proof source: it may only *add* tests to a selection, never remove any.

**Three linkage mechanisms already exist and share no table:** `functions.tests_raw` (author-declared
from a `{tests}` doc comment, never cross-checked against a run), `arch-coverage` (static span ×
runtime LCOV hits), and `arch-coverage-load` (dated runtime snapshots into the `coverage` table).
Test *identity* in both `arch-mutants` and `arch-impact` is a path/name heuristic, not a registry.

**Naming.** `mutation_sites` is taken and means imperative writes. New objects need a different
name; "mutant" and "mutant_kills" do not collide today.

**Provenance.** `docs/schema.md:74–96`: provenance is a `producer_runs` row plus a nullable
`producer_run_id` foreign key, deliberately not per-row text — at Octez scale the per-row form is
described as a ~200 MB mistake. Roadmap dependency 1.2 is satisfied by following that shape.

**Context manifest:** none. No claims reconciler is installed in this project
(`scripts/claims-reconcile.js` and `.harness/bin/claims-reconcile.js` both absent), so no
`context.manifest.json` was produced and no model/freshness digests are recorded.
