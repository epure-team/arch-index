## Decision: ordinal direction (last-bound keeps bare name)

**Decision:** the draft's convention is inverted and must be flipped. The **last** (source-order-final, i.e. the live/reachable) binding at a colliding `(module, name)` position keeps the **bare name**; every earlier (shadowed, dead) binding at that position takes the `#N` suffix, where `N` counts backward from the collision (or forward — exact numbering is an implementer detail, see below) among the shadowed bindings only.

**Why:** two independent lines of evidence converge, and I verified both directly:

1. **OCaml's own same-level shadowing semantics.** In `let f = e1 let f = e2`, only the second `f` is visible to any code after it, including any cross-module reference via the module's signature — the compiler's own environment model resolves `M.f` to the last binding, unconditionally. This was already implicit in the issue and in both voices' analyses.
2. **Cross-module call resolution is purely syntactic and bare-name-only.** `add_path_call`/`path_to_module_name`/`Head_qualified` (`arch_index_cmt.ml`, call sites at lines 460, 496, 546, 587, 882, 891, 897, 905, 921, 946, 1187, 1190, 1265, 1276) record a cross-module callee's name straight from the OCaml path text — there is no ordinal in that text and cannot be, because the caller sees only `M.f`, never `M.f#2`. Resolution then goes through `resolve_qualified` (`arch_index.ml:355-372`), a pure `(mod_path, qualified_name)` hashtable lookup against `fn_lookup`. If the bare name `f` is assigned to the *first* (shadowed, dead) definition — the draft's current behavior — every external caller of `M.f` is silently rebound onto dead code: the exact defect class issue #41 already describes, now reproduced on the cross-module axis the intake brief's Scope Boundary explicitly forbids making worse.

Flipping the convention (last-bound = bare name) makes the bare name always resolve to the one definition that is actually live and callable from outside the module, matching both the compiler's real shadowing semantics and every existing external caller's only possible spelling of the reference. It also restores the pre-fix external observable behavior for `arch-query`'s bare-name lookups (documented in the intake brief's "User-visible naming-contract change" note: before the fix, `INSERT OR REPLACE` always left the *last* definition standing under the bare name — the flipped convention reproduces that same external observable, just now with the earlier, shadowed definition additionally visible as `#N` instead of silently vanishing).

**Implementation implication:** `build_binding_names` must number bindings so that ordinal assignment is only fully determined once all bindings at a given base position are known (i.e. after a full pass over the structure, not incrementally in source order) — the current draft's `bind_last` field already computes a total count per base name, but the row-write site must key `exposed`/doc-comment gating and the **bare vs. `#N` name choice** both off "is this the last one," not off "is this the first one." Concretely: rename the draft's implicit "first occurrence gets no suffix" rule to "last occurrence gets no suffix, all earlier occurrences get `#N` counting up in source order among themselves (`#1`, `#2`, ... for the 1st, 2nd, ... shadowed definitions, reserving no suffix for the final one)." The `bind_last`-gated `exposed`/doc-comment logic is already correctly oriented in the draft and needs no change — only the **name string** assignment was inverted.

3. **Rebuild `tezt/tests/shadowed_definitions.ml` against current `main`'s test helpers**, correcting both fixtures for the flipped convention (the "shadow" fixture's row-identity assertions currently expect first-keeps-bare-name; these must be inverted to last-keeps-bare-name) and **add a new cross-module fixture**: module `A` with two same-named top-level bindings (each calling a distinct helper), module `B` calling `A.f` by qualified path — assert `B`'s call resolves to the *live* (last) definition's edges, not the shadowed one. This is the fixture that would have caught the draft's defect; its absence is exactly the corrected plan's answer to both voices' shared risk. Completion criterion: cross-module fixture fails against the (hypothetical) unflipped direction and passes against the corrected one — a real red-then-green proof, not just a passing test.
4. **Run the roadmap's soundness evidence gate**: `dune build`, `dune test --force`, `arch-rules --on-vacuous fail` over a self-index, and a self-index-scale MUST/MAY_TOP measurement before/after (Octez re-measurement deferred per intake brief, retained as a documented follow-up in the ship summary, not a blocker). Completion criterion: all gates pass; the self-index measurement shows the expected direction of change (fewer misattributed/dropped edges on the shadowed-binding axis) or is documented as inconclusive-but-not-regressive if the self-index has no such fixture naturally.
5. **Document the user-visible naming-contract change** in the PR description / ship summary per the intake brief's explicit requirement: bare-name `arch-query` lookups against a function name that was shadowed now return the *live* definition (matches pre-fix behavior) plus a newly-visible `#N` row for the shadowed one — not a behavior change for the bare-name case, but a new row appears where none did before.
