# Roster intake — documentation CI and agent guide

## Objective

Add one concise, language-neutral guide for a practical CI integration and
bounded agent use. It must distinguish briefing from gate, document an honest
interpretation of MUST/MAY/TOP and all unavailable/refused states, and route to
the existing detailed command contracts.

## Scope

Documentation only: `docs/ci-agent-guide.md`, its README route, and this intake
record. Do not alter CI policy, commands, schemas, producer coverage or MCP
credentials. Examples use placeholders where CI/provider or language setup is
project-specific.

## Acceptance

- A reader can identify the order: build/index, briefing, explicit rule gate.
- Examples neither equate MAY/TOP with certainty nor call missing/refused data a pass.
- The guide forbids score/count gates and describes artifact/provenance limits.
- Markdown links resolve; a maintainer review records the uncertainty check.
