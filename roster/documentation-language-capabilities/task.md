# Roster intake — documentation language capabilities

## Objective

Provide a short language/capability navigation page after the general README
and CI guide. It must describe the producer paths and their material limits,
link to the detailed OCaml CMT/functor material, and avoid claiming that an LSP
or NDJSON index is a sound/complete graph.

## Scope

Documentation only: the capability page, README/install routes, and this Roster
record. Do not change producer interfaces, CI setup, schemas or analysis policy.

## Acceptance

- A reader can select LSP, OCaml CMT, Go, Rust, or custom NDJSON without a
  promise of universal support.
- Each path states where coverage/provenance and uncertainty are checked.
- OCaml advanced content is linked from its path, not made the global default.
- Commands and Markdown links are locally checked; Roster review records limits.
