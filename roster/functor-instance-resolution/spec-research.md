## 1. Relevant paths and present contracts

- `lib/arch_index/arch_index_cmt.ml:162-198` is the shared definition traversal. It descends literal structures, functor bodies, constraints, named modules, recursive modules, and includes, but stops at `Tmod_apply`, `Tmod_apply_unit`, identifiers, and unpacking. A binding with `mb_id = None` is skipped (`:186-196`). The stated invariant is one row per definition, not one set per application (`:172-176`, `:2930-2936`).
- `lib/arch_index/arch_index_cmt.ml:721-738` extracts dependency targets only from `Tmod_ident`, optionally through constraints. `module_path_root` can traverse `Path.Papply` but is documented as returning no root for an application (`:740-743`). Alias collection is per-CMT and keyed by `Ident.unique_name`; only persistent-root targets are admitted, while applications, literal structures, unpacks, functor-parameter aliases, and unit-local aliases are declined (`:1044-1113`).
- `lib/arch_index/arch_index_cmt.ml:2518-2529` separately traverses functor bodies for calls in a deferred CFG block. This is call conditionality behavior, not module-application collection.
- `lib/arch_index/arch_index_cmt.ml:2745-2765` is the producer entry: `process_cmt` reads an artifact, accepts only `Implementation structure`, requires a recoverable source path, and returns empty triples for unsupported/absent cases. Its current public return boundary remains exactly `(pending_call list * pending_dep list * pending_type_usage list)` (`lib/arch_index/arch_index_cmt.mli:440-479`).
- The call payload is unchanged and application-agnostic: `pending_call` carries caller module/name, head, partial/conditional/dead flags, call site, exception/value-channel scopes, propagation channel, and edge form (`lib/arch_index/arch_index_cmt.ml:617-662`; public declaration `lib/arch_index/arch_index_cmt.mli:288-322`). Existing collection APIs expose no functor-application component (`lib/arch_index/arch_index_cmt.mli:398-430`, `:458-479`).
- `architecture-schema.sql:61-126` represents source files and static functions; function identity is `UNIQUE(module_id, name)`. `calls` represents call sites and target certainty, with no tuple uniqueness constraint (`architecture-schema.sql:208-283`). `module_deps` stores file-level open/include/alias/local-open relations (`:294-308`). No functor-application/module-instance table exists in the main schema.
- `lib/arch_index/arch_index_db.ml:31-90` defines the main schema version as `1.13` and describes additive changes as minor-version bumps; the flat schema is structurally separate (`:92-100`). `architecture-schema.sql:27-52` provides one `producer_runs` row per main-schema producer invocation; `lib/arch_index/arch_index.ml:459-492` creates that row before per-artifact processing and warns, but continues, if provenance insertion is rejected.
- `lib/arch_index/arch_index.ml:600-643` walks every discovered CMT inside one transaction, catches an exception per artifact, prints a warning, continues, and commits the successfully collected rows. Thus “run exited” and “every selected artifact decoded” are not currently the same state. The returned result exposes row counts plus `n_statement_failures` and per-table rejection counts; its contract explicitly says counts do not imply source completeness (`lib/arch_index/arch_index.mli:14-65`).
- `lib/arch_index/arch_index_support.ml:16-32` centralizes presence-based completion markers. Reindex deletes those markers before drop and again after schema recreation (`lib/arch_index/arch_index.ml:367-389`, `:433-457`). Producer-written tables are dropped/recreated using `schema_tables_to_drop` (`lib/arch_index/arch_index_support.ml:56-122`; `lib/arch_index/arch_index.ml:391-416`).
- Completion is earned late, not inferred from row counts: `callgraph_contract` and `exn_contract` are written only for a non-empty indexed function universe inside the call transaction, then committed (`lib/arch_index/arch_index.ml:1551-1570`); `error_contract` is written only after that commit (`:1571-1590`). A fully successful analysis may legitimately have zero evidence rows (`:1581-1583`).
- `bin/arch_query/arch_query.ml:137-170` opens the database through `Arch_db.open_ro` and dispatches commands through typed query shapes. The connection is genuinely SQLite read-only (`lib/arch_tools/arch_db.ml:383-390`). Schema/metadata probes already exist as `has_table`, `has_col`, and `meta` (`lib/arch_tools/arch_db.ml:344-377`).
- Query refusal is explicit and precedes output where absence would otherwise look empty: `escaping-origins` checks main-schema tables, feature table, then required column and exits 3 with a scoped refusal (`bin/arch_query/arch_query.ml:458-494`); exception queries call `Arch_exn.load` before printing an answer (`:1490-1500`). Driver-detected missing tables/columns are converted to a refusal backstop (`lib/arch_tools/arch_db.ml:100-148`).
- Documentation entry points are `README.md:73` for the existing “not analysed” versus empty-result distinction, `docs/schema.md` for main-schema history (referenced by `lib/arch_index/arch_index_db.ml:31-40`), and `README.md`/the `arch-query` usage block at `bin/arch_query/arch_query.ml:1-116` for user-visible commands.

## 7. Existing assumptions opposite a catalogue

- The shared definition traversal intentionally treats application expressions as terminal so applications never multiply static definition rows (`lib/arch_index/arch_index_cmt.ml:167-176`, `:191-198`). Two native fixtures assert this absence as correct behavior (`tezt/tests/ocaml_shapes.ml:256-265`; `tezt/tests/callgraph_nested.ml:202-207`).
- The only public producer result from one CMT is the three-list pending tuple; callers destructure exactly those three values (`lib/arch_index/arch_index_cmt.mli:440-479`; `lib/arch_index/arch_index.ml:608-636`). There is no present fourth application-fact stream.
- Dependency extraction equates “recordable module target” with an identifier path under optional constraints. Ordinary/unit applications and anonymous structures currently become no dependency fact (`lib/arch_index/arch_index_cmt.ml:721-738`; `specs/reexport-resolution.md:23-39`).
- Alias normalization deliberately rejects application expressions as things that do not name a module defined elsewhere (`lib/arch_index/arch_index_cmt.ml:1072-1104`). This preserves a top call-head rather than inventing a definition identity.
- Static function identity and call consumers assume one function per definition and no runtime/application-specific cloning (`architecture-schema.sql:81-126`; `lib/arch_index/arch_index_cmt.ml:2930-2936`). Existing graph semantics consume only `calls` plus completion metadata (`architecture-schema.sql:208-288`); no current call-resolution input or output references application occurrences.
- Presence of rows is not a completion signal. Existing consumers rely on an explicit contract marker and refuse when capability/evidence is absent (`lib/arch_index/arch_index_support.ml:16-32`; `bin/arch_query/arch_query.ml:458-494`). Per-artifact exceptions are currently warnings followed by continuation (`lib/arch_index/arch_index.ml:605-643`), so a catalogue covering only successfully decoded implementations would coexist with a run that also encountered failed/ignored artifacts unless its state is represented separately.
- Binder stamps are safe only within the artifact walk: the repository documents `Ident.unique_name` stamps as per-compilation-unit identities, not cross-build persisted identifiers (`lib/arch_index/arch_index_cmt.ml:1055-1062`; `lib/arch_index/arch_index_cmt.mli:390-395`). Installed `module_expr` provides no UID, while `mb_uid` identifies the declaration containing an expression (`typedtree.mli:425-431`, `:485-494`).
- Existing source provenance uses source-relative module paths and line-oriented call sites, while `Location.t` can be ghost or carry exceptional position encodings (`lib/arch_index/arch_index_cmt.ml:2760-2779`, `:617-633`; installed `location.mli:25-35`).

The unchanged-call-graph contract is therefore concrete: keep definition traversal semantics, `pending_call`, the three-list `process_cmt` return shape as consumed by the main run, `calls` rows/kinds/top reasons/edge forms, completion markers, and graph-query verdicts observationally unchanged. The repository currently has no application catalogue consumer in that call path.
