# R1 Correction Plan — Architecture Voice 1

## 1. Numbered plan with dependencies

1. **Freeze the R1 correction contract before changing implementation.** Amend the existing arch-guard specification in the already named component/test/docs scope to make the installed `arch_guard` executable and root `arch-guard` dispatcher the only supported public interfaces; declare `lib/arch_guard` private; freeze the existing CLI flags, closed JSON fields, text projection, exit mapping, resource bounds, input acceptance rules, status/reason rules, sorting, and census semantics. Add a report-context matrix that applies equally to non-empty and accepted-empty inventories and explicitly requires linked compiler identity, host 31/63-bit width, supplied-artifact scope, trusted same-compiler/same-target and no-source-freshness assumptions, plus the stated completeness, execution, failure, proof, interprocedural, heap, indirect-operation, and omitted-artifact limitations. Define a single canonical result model from which JSON and text are rendered; do not add a second schema or an embedding API. Freeze exact reason identifiers/order and the canonical text representation of every JSON field before fixtures depend on them. **Dependencies:** validated intake only. **Exit criterion:** every amended behavior has an unambiguous expected output or rejection, including empty inventory, and none of the existing 47 functional requirements or 19 acceptance criteria is weakened.

2. **Correct package and runtime boundaries as one installable vertical slice.** Update the private library/executable/wrapper packaging and CLI lifecycle so compiler global state may be reset inside the CLI process without promising restoration to an embedding host. Keep owned probe linkage working, ensure the root dispatcher delegates without building or discovering projects, and add an installation-manifest assertion that the public executable is present while the private library is absent. Exercise `--help`, `--version`, direct executable invocation, wrapper invocation, and wrapper behavior when the executable is missing; the missing case must diagnose and fail without auto-building. **Dependencies:** step 1. **Exit criterion:** fresh installation metadata and process-level probes demonstrate exactly the frozen public surface.

3. **Correct report context through the canonical result path.** Populate all required context and limitations before rendering, including accepted empty inventories, and project both formats from that same value. Preserve the closed JSON schema rather than introducing ad hoc fields unless the frozen existing schema already provides the required locations; if it cannot represent an amendment requirement, stop and resolve the contract conflict rather than silently opening the schema. Keep status semantics strict: `ZERO` is conditional on reaching a site, `MAY_ZERO` is not a confirmed failure, `UNREACHABLE` is model-relative, and `UNSUPPORTED` cannot be emitted with only a numeric uncertainty reason. **Dependencies:** steps 1–2. **Exit criterion:** a fixture containing all five statuses and an empty fixture produce complete, honest context in both formats with identical site data and census.

4. **Harden primitive inventory and operand reconstruction at the Typedtree/CMT seam.** Add owned native or trusted seam fixtures for later saturation, overapplication, labelled operands, absent original slot 2 followed by later arguments, and combined eligibility/ancestry exclusions. Preserve immediate-site cardinality and original operand-slot metadata; partial or malformed applications remain inventoried and unsupported rather than being reinterpreted as executions. Distinguish typed `Val_prim` identity from shadowed operators, indirect/unlisted calls, methods, and effect primitives. Cover unresolved or non-native operand and guard types and exact 256/257 UTF-8-byte spelling boundaries. Assert stable source coordinates, duplicate-coordinate handling, primitive identity, operand category, status-specific reasons, and exact sorted multi-reason output. **Dependencies:** step 1; may proceed after the data model portion of step 3 is fixed, but must land before the JS oracle. **Exit criterion:** inventory tests prove that eligibility, argument position, ancestry, and reason accumulation cannot hide or duplicate a syntactic site.

5. **Harden abstract interpretation and entry-context isolation end to end.** Extend numeric and native-fixture coverage for alpha-renaming; aliases established before and inside refinement; fresh nested, curried, and immediately applied function entries below nonzero, contradictory, and unsupported ancestors; inner locals; defaults/cases; unaffected siblings; every loop operand/body/result position; and multiple simultaneous exclusion causes. Nested functions always start with unknown parameters/captures and inherit no parent reachability guarantee. Unsupported structural/effectful regions must remain unsupported, while sibling supported regions remain analyzable. Retain conservative 31/63-bit modular behavior, bottom/top distinction, branch restriction and join laws, and never concretely divide by zero. Include sensitivity controls that fail when a status has the wrong reason or an unsupported site has only a numeric reason. **Dependencies:** steps 1, 3, and inventory identities from step 4. **Exit criterion:** domain containment/law tests and authentic compiled fixtures jointly cover all amendment cases without creating interprocedural, heap, loop, exception, effect, mutation, or default-argument semantics.

6. **Prove format equivalence, deterministic ordering, and input-set behavior.** On an all-five-status fixture, parse JSON and text and compare every site field, context item, reason, and census rather than checking selected substrings. Add omitted-text-field and wrong-reason mutation/sensitivity controls. Run two distinct accepted inputs in both orders and require byte-for-byte identical output; separately verify duplicate physical-path deduplication, rejection of duplicate module/source identity, duplicate source coordinates without accidental coalescing, symlink rejection, changed-input handling, and accepted-empty output. Preserve exit 0 for completed reports regardless of finding status and exit 2 for command/input/internal failure with no complete JSON. **Dependencies:** steps 3–5. **Exit criterion:** output is a deterministic function of the accepted artifact set, not argument order or renderer-specific logic.

7. **Add the standalone report-context regression ratchet last.** Create exactly `scripts/check-guard-report-context.js` as a self-contained, no-required-argument executable targeting finding `lib/arch_guard/arch_guard.ml:213:spec#cd378d70` and pre-fix SHA `d44c0c6ae8f4991549f6de5bbc2bdb3f24eb25ec`. It compiles owned empty and classified fixtures, invokes the actual CLI in JSON and text modes, enforces 120-second and 16-MiB child caps, and returns 0/pass, 1/assertion, and at least 2/setup or execution. It must use an already built CLI in normal runs; only in the isolated pre-fix archive may it build the single CLI target when absent, using the caller's configured compiler environment. The red/green procedure overlays only this file onto the pre-fix archive, so it must not import new helpers or depend on corrected-tree artifacts. Capture an authentic pre-fix assertion failure and corrected success, then register the script in Tezt without causing nested Dune when the suite supplied the binary. Do not broaden script manifests. **Dependencies:** steps 2–6, because the oracle must ratchet the final public behavior rather than drive an unstable contract. **Exit criterion:** archive red and corrected-tree green are reproducible under the same checker and bounded child execution.

8. **Align durable user-facing claims and owned census evidence.** Update `docs/arch-guard.md`, README, CHANGELOG, and the roadmap to match the frozen public surface, report context, limitations, exit semantics, and report-only nature. Run arch-guard on owned library artifacts and publish an honest zero-site result if applicable; keep unsupported denominators and useful `NONZERO`/`UNREACHABLE` distinctions visible. Preserve R1 findings and cross-runtime degraded evidence rather than rewriting history. **Dependencies:** steps 1–7. **Exit criterion:** documentation makes no whole-program, guaranteed-execution, confirmed-vulnerability, machine-proof, freshness, or target-correspondence claim beyond the emitted evidence.

9. **Execute serialized release gates and obtain independent verdicts.** With no concurrent Dune in the active worktree, run whitespace checking, full installation-target build, forced full suite, all standalone checks, fresh self-index/golden, recalibration check, vacuity-failing arch-rules self-check, arch-impact self-check, origin-consumer plus artifact validation, and a clean-build recalibration committed only after its generated state is understood and owned. Confirm existing origins, rules, references, extraction behavior, and verdicts remain unchanged. Then request a fresh independent roster review and QA; do not open a PR until both report GO. Clean only owned disposable artifacts. **Dependencies:** steps 1–8. **Exit criterion:** every gate passes from a clean state, installation manifest assertions pass, review and QA are GO, and no unrelated change remains.

## 2. Assumptions

- The original implementation, its 47 functional requirements, 19 acceptance criteria, existing fixture harness, CLI contract, and pre-fix archive are available in the correction worktree; the implementation phase may inspect them, although this plan intentionally derives only from the validated intake.
- The existing closed JSON schema has designated fields capable of carrying all amended context and limitations. If it does not, that is a contract conflict, not permission to add fields autonomously.
- The configured OCaml 5.3-or-newer switch and already declared dependencies are sufficient. Any new dependency requires an explicit repository-level justification and must not be installed globally.
- Owned fixtures can be compiled with the caller's compiler environment and can produce both empty and classified CMT artifacts without executing arbitrary target projects.
- The test harness can impose wall-clock and memory limits portably enough for supported CI; inability to enforce either limit is a failed gate, not a reason to omit it.
- Exact-head remote CI, installation manifest generation, self/golden/origin gates, and independent roster review/QA are available before merge.

## 3. Risks

- **Closed-schema conflict:** required report context may not fit the existing schema. Quietly adding keys breaks the amendment; compressing claims into unrelated fields makes consumers ambiguous. Treat this as a stop condition requiring contract resolution.
- **Renderer drift:** independently assembled text and JSON can pass shallow tests while disagreeing on scope, reasons, coordinates, or census. A canonical result and exhaustive cross-format comparison are mandatory.
- **False precision through ancestry leakage:** branch facts or unreachable state can leak into nested/curried/default/case entries, incorrectly producing `NONZERO` or `UNREACHABLE`; fresh entry-state tests must be adversarial.
- **Operand-slot corruption:** saturation, labels, overapplication, or missing slot 2 can shift later arguments into the divisor position. Inventory must retain compiler-origin slots and classify ambiguity as unsupported.
- **Unsupported laundering:** mixed numeric and structural exclusions can collapse to a numeric `MAY_ZERO`, hiding unsupported semantics. Status precedence and complete sorted reason sets must be asserted.
- **Arithmetic unsoundness:** host-width calculations or unbounded integers can prove nonzero across modular wraparound. Small-width exhaustive containment and 31/63-bit extrema remain release gates.
- **Non-hermetic ratchet:** the JS check could accidentally use corrected helpers, a stale CLI, nested Dune, unbounded children, or the wrong compiler, yielding a meaningless red/green result. The archive overlay and process controls must be independently observable.
- **Nondeterminism and accidental coalescing:** argument order, canonical-path deduplication, duplicate module identities, or equal source coordinates can perturb output or site counts. Each mechanism needs a distinct fixture and assertion.
- **Packaging regression:** making the library private may break owned probes, while manifest checks against a stale build can falsely pass. Verify from freshly generated installation metadata and retain explicit probe linkage.
- **Baseline collateral:** broad fixture/script manifest edits or recalibration can alter arch-index extraction, rules, or reference outputs. Restrict edits to named paths and inspect every baseline delta before commit.

## 4. Questions requiring resolution during specification freeze

1. Which exact existing JSON fields and text labels carry each required context/limitation item, and what is their canonical order? This must be answered from the existing contract before implementation; adding fields is not authorized by the amendment.
2. What are the exact closed reason identifiers and precedence when numeric uncertainty, operand ineligibility, and unsupported ancestry coexist? The plan requires all applicable reasons sorted, but the authoritative spelling must be frozen from the existing specification.
3. What is the authoritative serialization for duplicate source coordinates: separate stable records with a deterministic tie-breaker, or an explicit rejection? Sites must never be silently merged, but the intake does not select between those public behaviors.
4. Which command-line flags name JSON/text modes and version output, and what exact diagnostic/no-output behavior is required when the wrapper cannot find the installed executable? Existing public behavior should be preserved and tested rather than guessed.
5. How is the 16-MiB child cap defined on supported CI platforms—address-space, resident memory, or another enforceable process limit—and which child processes inherit it? The checker must fail setup if its promised cap cannot be established.
6. What constitutes the canonical pre-fix archive for SHA `d44c0c6ae8f4991549f6de5bbc2bdb3f24eb25ec`, and how is the authentic red result retained without committing disposable build outputs?
7. Which exact standalone checks comprise “all standalone checks,” and what command proves the installation manifest is freshly generated rather than reused? These commands must be frozen before the final gate run.
8. What repository mechanism records the required fresh independent roster review and QA GO verdicts, and what constitutes exact-head remote CI evidence? No PR proceeds until these evidence locations are explicit.
