# Research report: Q2, Q3, Q4

## Q2 — Existing syntax/operand classification and Typedtree/CMT consumption

- The OCaml indexer recursively finds `.cmt`/`.cmti` files, excludes dune alias modules, and sorts paths in `lib/arch_index/arch_index_cmt.ml:319-340`. Interface metadata is read with `Cmt_format.read`; `Interface` annotations are traversed as `Typedtree.signature_item`s in `lib/arch_index/arch_index_cmt.ml:349-366`. Main indexing again uses `Cmt_format.read`, accepts only `Implementation structure`, and takes the compiler unit identity from `info.cmt_modname` in `lib/arch_index/arch_index_cmt.ml:2751-2765`.
- Structure traversal is Typedtree-based: `iter_structure_items` accepts `Typedtree.structure`, dispatches on `Tstr_module`, `Tstr_recmodule`, and `Tstr_include`, and otherwise stops structural descent at that level (`lib/arch_index/arch_index_cmt.ml:178-185`). Expression traversal is a `Tast_iterator.default_iterator` override (`lib/arch_index/arch_index_cmt.ml:1642-1647`), with explicit handling for function/let/lazy/object/if/match/try/while/for/assert/letop/apply/sequence and a final default Typedtree descent (`lib/arch_index/arch_index_cmt.ml:1682-2022`, `lib/arch_index/arch_index_cmt.ml:2404-2517`).
- Applied compiler primitives are identified from the typed identifier descriptor, specifically `Texp_ident (_, _, {val_kind = Val_prim {prim_name; _}; _})`, rather than source operator spelling. Raise primitives use this identity in `lib/arch_index/arch_index_exn.ml:101-112`; other raising primitives are classified by `prim_name` in `lib/arch_index/arch_index_exn.ml:430-447`, and the CMT walker invokes that classifier at applications in `lib/arch_index/arch_index_cmt.ml:2395-2399`.
- The primitive table classifies polymorphic comparisons as `P_compare`; `%divint`, `%modint`, and the int32/int64/nativeint division and remainder primitives as `P_division`; and safe array/string/bytes accesses as `P_index` (`lib/arch_index/arch_index_exn.ml:435-447`). Comparison classification further consults Typedtree argument types: predefined closure-free ground types and recursively closure-free list/option/array/tuple types suppress an origin; other type shapes are treated as potentially raising (`lib/arch_index/arch_index_exn.ml:449-477`).
- Division operand context is syntax-only and tied to original argument slot 2. It records primitive, slot, category, optional representation, integer kind, and optional unavailability reason (`lib/arch_index/arch_index_exn.ml:61-68`). Slot 2 is classified as `integer_literal` for `Const_int`, `Const_int32`, `Const_int64`, or `Const_nativeint`; `identifier` for `Texp_ident` (representation capped at 256 bytes); `other` for every other expression; and `missing` when the original slot is absent (`lib/arch_index/arch_index_exn.ml:478-506`). Tests pin identifier, literal-without-evaluation, complex-expression-as-other, and partial-application-as-missing behavior in `tezt/tests/exn_raise_sets.ml:296-311`.

Coverage boundaries visible in code:

- The primitive classifier is a closed match and returns `None` for every unlisted primitive (`lib/arch_index/arch_index_exn.ml:437-447`).
- Operand syntax recognizes only literal constants and identifiers; all other divisor expressions collapse to `other` without a representation (`lib/arch_index/arch_index_exn.ml:486-502`).
- Typedtree expression constructs not explicitly lowered fall through to the compiler default iterator (`lib/arch_index/arch_index_cmt.ml:2516-2517`): their children are visited, but no dedicated CFG shape is added.
- Function-case literal return extraction explicitly returns `None` for `Tfunction_cases` (`lib/arch_index/arch_index_cmt.ml:1566-1573`).

The key distinction is that primitive recognition uses compiler primitive identity from the Typedtree value descriptor, not the source spelling or printed path.

## Q3 — Existing integer semantics

- The code distinguishes four integer kinds solely by primitive identity: `int32`, `int64`, `nativeint`, and otherwise `int` (`lib/arch_index/arch_index_exn.ml:478-485`). Literal text is obtained with `string_of_int`, `Int32.to_string`, `Int64.to_string`, or `Nativeint.to_string` (`lib/arch_index/arch_index_exn.ml:491-496`). The consumer validates the exact primitive vocabulary and primitive-to-kind mapping in `lib/arch_tools/arch_origin_context.ml:134-152`.
- Every recognized integer division/remainder primitive records a `Division_by_zero` origin plus operand metadata (`lib/arch_index/arch_index_exn.ml:478-506`). The transitive exception analysis treats the corresponding Stdlib division/remainder functions as known external leaves because their effect is already represented by the origin (`lib/arch_tools/arch_exn.ml:95-114`).
- The stored divisor information is syntactic, not an abstract or evaluated integer value. Original slot 2 is retained as literal text, identifier text, `other`, or `missing` (`lib/arch_index/arch_index_exn.ml:486-505`); the test explicitly states that a literal is recorded “without evaluating it” (`tezt/tests/exn_raise_sets.ml:300-307`).
- No machine-word-width calculation, integer range domain, arithmetic evaluator, constant propagation, overflow rule, or signed quotient/remainder computation is present in the searched live OCaml implementation. A division origin is recorded irrespective of whether a literal divisor is visibly nonzero (`lib/arch_index/arch_index_exn.ml:486-506`). The represented semantics are therefore primitive/kind classification and possible `Division_by_zero`, not quotient, remainder, overflow, or machine-width value semantics.
- Unknown or unsupported operand expressions are represented as category `other`, `representation = None`, with an unavailability reason; omitted original slot 2 is `missing` with a separate reason (`lib/arch_index/arch_index_exn.ml:486-505`). Separately, unknown exception values are represented as exception-lattice top with an `unknown_exn_value` witness (`lib/arch_tools/arch_exn.ml:497-513`). There is no integer top/bottom abstract value in these files.

The key distinction is between a stored syntactic divisor and value semantics: the implementation preserves selected Typedtree syntax but does not interpret its numeric value.

## Q4 — Existing control-flow and abstract-domain handling

- Per-function CFG state is `Arch_index_cfg.t`: integer-numbered blocks, successor lists, and a per-block terminated flag (`lib/arch_index/arch_index_cfg.ml:20-30`). A solved verdict carries three separate Boolean arrays: `always` (post-dominates entry), `reachable` (reachable from entry), and `live` (reachable from entry or a registered deferred root) (`lib/arch_index/arch_index_cfg.ml:62-67`).
- Branch lowering creates explicit arms and join blocks. `if` evaluates the condition before branching, with an absent else connected directly to the join (`lib/arch_index/arch_index_cmt.ml:1782-1800`). `match` walks the scrutinee first, creates one block per arm and a join, and adds a bypass-to-join for `Partial` matches (`lib/arch_index/arch_index_cmt.ml:1801-1905`). `try` uses a handler dispatch block, normal-body and dispatch edges, per-handler blocks, and a common join (`lib/arch_index/arch_index_cmt.ml:1906-1942`). While and for loops create head/body/after blocks and back edges, with an exit edge even for syntactically constant-true while conditions (`lib/arch_index/arch_index_cmt.ml:1943-1977`). Let-operator continuations are explicit conditional branches with a bypass and join (`lib/arch_index/arch_index_cmt.ml:1987-2011`).
- Diverging applications first add any active handler-dispatch edge, then mark the current block terminated and continue walking in a fresh block with no incoming edge (`lib/arch_index/arch_index_cmt.ml:1621-1632`). CFG edges added after termination are ignored (`lib/arch_index/arch_index_cfg.ml:50-60`). Post-divergence calls therefore remain recorded while being entry-unreachable.
- `solve` adds a virtual exit to terminal and terminated blocks, computes entry reachability and deferred-root liveness, then computes post-dominance via iterative successor-set intersection to a fixpoint (`lib/arch_index/arch_index_cfg.ml:85-152`). `always_exec`, `reachable`, and `may_run` are bounded array lookups returning false out of range (`lib/arch_index/arch_index_cfg.ml:155-165`). At call finalization, absent CFG context conservatively means conditional/demoted and never dead (`lib/arch_index/arch_index_cmt.ml:2691-2704`).
- The exception abstract domain is `Known of StringSet` or `Top of known StringSet * reason set`; it has no distinct `Bottom` constructor, and `Known empty` serves as the empty/bottom-like value for no known contribution (`lib/arch_tools/arch_exn.ml:57-65`, `lib/arch_tools/arch_exn.ml:497-513`). Join unions known sets and reason sets, with `Top` absorbing `Known` (`lib/arch_tools/arch_exn.ml:464-474`). A catch-all handler closes any value to `Known empty`; finite catches subtract paths from `Known` and only from `Top`'s known component, leaving `Top` itself (`lib/arch_tools/arch_exn.ml:478-495`). A worklist recomputes each node by joining its direct contribution with every edge contribution and queues predecessors on change (`lib/arch_tools/arch_exn.ml:533-562`).
- Unsupported or unknown call targets become `Head_unknown` with reason categories including callback/local computed value, module parameter, dropped node, or ambiguous unit (`lib/arch_index/arch_index_cmt.ml:538-614`); computed function arguments fall to `Head_unknown ("*TOP*", Callback_param)` (`lib/arch_index/arch_index_cmt.ml:1395-1437`). In exception propagation, `MAY_TOP`/top-sentinel edges produce `Top` with a witness, unrecognized external callees produce external `Top` unless a hypothesis or summary applies, and an absent solved internal callee contributes `Known empty` (`lib/arch_tools/arch_exn.ml:517-531`).

Coverage boundaries visible in code:

- The CFG performs no constant folding, so `while true` retains an exit path (`lib/arch_index/arch_index_cmt.ml:1943-1947`).
- Ordinary assertion may-raise behavior is not modeled as a branch or terminator, while `assert false` is (`lib/arch_index/arch_index_cmt.ml:1978-1986`).
- Unhandled Typedtree constructors receive default recursive traversal and no dedicated control-flow edges (`lib/arch_index/arch_index_cmt.ml:2516-2517`).
- Deferred lazy/object/functor/default bodies are isolated and separately marked live rather than connected to entry (`lib/arch_index/arch_index_cmt.ml:1247-1254`, `lib/arch_index/arch_index_cmt.ml:1776-1781`, `lib/arch_index/arch_index_cfg.ml:76-84`).

The key distinction is between intraprocedural graph state and its solved reachability facts: mutable CFG state is `n_blocks`/`succs`/`terminated`, while `always`/`reachable`/`live` are separately computed Boolean sets.
