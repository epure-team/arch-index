# Task — shadowed-function-identity

Fix roadmap item 0.6 / GitHub issue #41: same-level shadowing silently merges two functions into one node, and their call edges with them. This is a soundness bug in lib/arch_index/arch_index_cmt.ml's call-graph indexing: a compilation unit binding the same name twice at the same level currently produces only one row in `functions` (INSERT OR REPLACE on UNIQUE(module_id, name) drops the earlier one), and both bodies' outbound call edges resolve post-hoc by (module, name) onto the single surviving row, crediting it with calls it never makes.

Full issue text via `gh issue view 41` in /home/mathias/dev/arch-index. Fix direction from the issue: give shadowed same-level bindings distinct identities via a #N ordinal, mirroring the ordinal `lambda_name` already uses for synthetic lambda nodes.

Substantial prior work already exists, uncommitted, in worktree /tmp/claude-1000/-home-mathias-dev-arch-index/14fbc421-dfc7-4b31-91d6-c084baeb45e0/scratchpad/wt-rowid, branch fix/shadowed-function-identity, based on a stale commit 161f3d7 (~15 commits behind current main 014becd). It adds a `binding_identity`/`build_binding_names` mechanism, threads it through the main indexer and the sibling `call_graph_extractor.ml` LSP/flat-schema path, and adds tezt/tests/shadowed_definitions.ml. Treat it as a strong starting draft — investigate it, don't discard it, but re-derive correctness rather than trusting it blindly, especially: does `fn_lookup` in arch_index.ml (which resolves call edges post-hoc by name) get updated to use the ordinal-qualified name; does the new bare-name resolution semantics (first definition wins, not last) get stated as a user-visible naming-contract change for arch-query consumers; is `functions` still INSERT OR REPLACE (meaning the real ratchet is "two rows exist AND each keeps its own edges", not just "no statement failures").
