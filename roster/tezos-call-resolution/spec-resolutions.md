# Adversarial resolutions

All eight challenges came from a fresh Sol requirements pass, not a self-approval. No unresolved user preference or scope expansion remains.

| ID | Resolution and observable obligation |
|---|---|
| C-1 | Root lookup MUST use compiler binding identity within one CMT (Ident.same-compatible identity; existing unique_name keys are permissible only within that CMT). A printed root/name or a global stamp match is forbidden. Subsequent member names select only among exports of that proven structure. Homonymous roots in nested scopes and different CMTs must select their own bodies or refuse. |
| C-2 | Process binding/export effects in source order. All value names bound by a pattern mask prior same-name exports; only a plain variable with Texp_function RHS may install an eligible body. Value rec groups use their actual binder identities. Store each body's existing binding_name, including #N. A later nonbody or unsupported binding must never reveal an earlier body. |
| C-3 | Only Tmod_structure reached through Tmod_constraint is a transparent structure. Literal include bodies may contribute their actual final members under the enclosing scope; opaque includes mask all value/module names in incl_type, without claiming their bodies. Later explicit declarations can replace these masks. Test before/include/after collisions. |
| C-4 | Every module hop must identify a concrete structure, not an alias, parameter, functor/application result or unpack. Any unproven hop refuses the entire path. Recursive declarations with literal structure bodies can be indexed by their own identities without following recursive references; a path through an alias/cycle refuses. Nested direct structures inside functor definitions retain definition-only semantics. |
| C-5 | Eligibility uses the existing is_function_rhs predicate (Texp_function); arity uses existing fn_arity. Constraints in exp_extra do not erase that body. Applied new heads remain enumerated even when saturated. Underapplication remains partial, and application beyond the known body's syntactic arity must keep/add the computed-return TOP residual. Never delete an existing residual merely because a body target is known. |
| C-6 | Preserve caller, source location, CFG cond/dead, scope links, channel propagation classification and site form. Ordinary calls are not module_alias merely because their root is local. Existing value_alias emission keeps that marker and its ordinary-head/kind-matrix contract. A resolved head becomes MAY_ENUMERATED with null TOP fields; dropped target remains TOP/dropped_node via existing global resolution. No unrelated rows may change. Additional return-residual TOP is allowed only where C-5 requires it and is separately witnessed; it is not a resolution gain. |
| C-7 | Canonical primary set tuple: caller path/name, call_site, target path/name; exclude value_alias only. Canonical row multiset additionally includes original callee display, kind, edge_form, top_reason and top_anchor, retaining nulls. Compare multiplicities, not pairwise SQL joins. Existing resolved tuples/kinds must survive unchanged; same-line reorder is neutral, duplicate deletion is a failure. New duplicates of an existing relation add no metric gain. No claim to distinguish permutations of truly indistinguishable rows. |
| C-8 | First-slice allowed changes are same-file function-body candidates replacing module_param TOP heads, with stored target identity and full old/new group rows retained; value_alias changes are excluded from gain. Every changed group must fit the supported native fixture behavior, with source/target positions available for independent review. Existing target loss, new MUST, disappearance of unrelated TOP/refusal rows, incomplete corpus or changed inputs is a hard refusal. Semantic correctness rests on the identity-based transformation plus native regression/refusal tests and independent review; the count/comparator is not represented as an arbitrary-program correctness oracle. Unsupported/unclassifiable changes cannot authorize keep. Positive gain, passing full guards and review/QA/CI are all required. |

## Cross-spec handling

No new entity redefines an existing entity from specs/* Entities sections. This feature does not amend persistent module-alias resolution or value-alias target eligibility. It preserves their existing emission forms and kind-matrix rules. The new private head form, if needed to preserve separation of identity/certainty, must be documented explicitly rather than overloading an alias marker or a partial flag for demotion.

The flat fallback lacks rich-schema ordinal-qualified nested function rows. Its compatibility obligation is correct same-file target attribution when an eligible stored row exists and no name-only cross-file fallback for newly proven local targets; no new nested caller coverage or fictitious flat target is promised. Plan must decide the smallest representation that preserves this distinction.
